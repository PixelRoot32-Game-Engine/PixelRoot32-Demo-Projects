# legend_of_clone — asset tools

Nothing here is compiled or shipped, and **nothing here is versioned** —
`docs/audits/` is gitignored. These scripts stand in for the PixelRoot32
**Tilemap Editor** and **Sprite Compiler**: they take an authoring format a
human can edit and emit the same C++ those tools emit, into
`games/legend_of_clone/src/assets/`.

That split is the same one metroidvania has. Its assets say `// Generated by
PixelRoot32 Sprite Compiler` and the compiler is not in the repository either.
The **output** is what the repo carries and what reviewers read.

| File | What it is |
| --- | --- |
| `art_source.py` | The authoring format. Every pixel, every map cell, every color. This is the file you edit. |
| `generate_assets.py` | The exporter. Writes the example's `src/assets/*.h\|.cpp`. |
| `verify_export.py` | Unpacks the generated C++ back to characters and diffs it against `art_source.py`. |
| `check_maps.py` | Validates both maps against their room tables and the doorway constants. |
| `check_sprites.py` | Measures every sprite against its own mirror, and against the others. |
| `preview.py` | Renders a room from the generated assets to PNG, so you can look at it. |
| `sheet.py` | Renders every player sprite zoomed with a pixel grid, for editing the character. |
| `locate.py` | Finds the example. These tools sit outside the tree they write to, so the distance is not fixed. |

```bash
python generate_assets.py   # after editing art_source.py
python verify_export.py     # then always this
python check_maps.py        # after editing a map
python check_sprites.py     # after editing the character
python preview.py           # when you want to see it in a room
python sheet.py             # when you are editing the character
```

`verify_export.py` is not optional after a change to the exporter. The bug it
guards against — a reversed nibble order — mirrors each *pair* of pixels and
produces art that looks almost right, which is far harder to catch by eye than
art that looks broken.

`check_sprites.py` is not optional after a change to the character. It fails on
a sprite that has become left-right symmetric, because the walk cycle spends the
flip bit as an animation frame for the vertical directions — a symmetric sprite
animates into itself and reads as a broken timer rather than as broken art. It
also reports mirror pairs, so a bitmap that has become redundant shows up as
128 bytes you can stop storing rather than as nothing at all.

Both render scripts write PNGs next to themselves. **Look at the render.** Do
not reason about the palette — the two-hop resolution (pixel value → `Color`
slot → RGB565) fails in ways that produce a plausible wrong picture rather than
an obvious one.

Both take an optional path to the example, for a worktree or a checkout
elsewhere:

```bash
python generate_assets.py /path/to/PixelRoot32-Demo-Projects/games/legend_of_clone
```

**Commit the generated files** in the example. An example has to build for
someone who has never run a Python script — and who will never have this folder.

## Why characters and not hex

A real project ships the packed bytes straight out of the editor, because nobody
edits 128 bytes of hex by hand. This example inverts that for authoring only,
because the art *is* what is being reviewed here — a bush you can see in a diff
is worth more than a hex blob, and eight rooms of level design are only
reviewable as a grid.

The inversion stops at the generator. The runtime gets packed 4bpp in flash,
byte-identical to an editor export: no packer, no `.bss`, no startup cost.

## What `generate_assets.py` decides so nothing else has to

- **Nibble order.** Within a byte the low nibble is the *left* pixel. Reversing
  it mirrors every pair of pixels — art that looks almost right, which is harder
  to spot than art that looks broken.
- **Palette slots.** Each color keeps its conventional engine `Color` slot, so
  `Color::White` is still white for status text. Packing slots tight instead
  would save nothing and would silently draw the status bar black on black.
- **Pixel value 0 is transparent.** The blitter never reads palette entry 0, so
  black lives at pixel value 1. This is why the exported `PALETTE_MAPPING` is
  not the identity.
- **Per-group palettes.** Each palette is built from the characters that group
  actually uses, so adding a color to `art_source.py` costs nothing until art
  references it.

## What `check_maps.py` catches

Failures that do not look like bugs from the code, and produce a game that runs
and misbehaves:

- a room border declaring a connection the tiles wall off
- an edge opening with no connection behind it — usually a forgotten room-table
  entry, not a deliberate dead end
- an unsealed outer border
- a spawn cell that lands on the very tile that triggers a scene change, which
  would bounce the player straight back where they came from
